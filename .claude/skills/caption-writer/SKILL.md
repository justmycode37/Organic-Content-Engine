# Caption writer

Write a caption that makes the Reel useful in text form and preserves the same evidence boundaries. The first line should state the finding or practical payoff, not tease a fact withheld until later.

## Structure

1. **First line:** a concrete result or useful distinction in plain English.
2. **Context:** two or three short paragraphs with the change, mechanism, scope, and who it affects.
3. **Qualification:** availability, test condition, denominator, uncertainty, or limitation that changes how the claim should be understood.
4. **Source attribution:** name the primary source if directly checked; otherwise accurately credit the secondary source and say what remains unavailable. Link only known, checked URLs.
5. **One CTA:** a relevant save, share, follow, or practical action. No pile of CTAs and no engagement bait.

Use ordinary punctuation, readable paragraphs, and no hashtag block. Add a hashtag only when it is specific and useful; it is optional. Never invent a source link, quote, metric, experiment, first-hand experience, or viewer reaction. Keep rumors attributed and distinguish announced, demonstrated, available, and shipped states.

## Example: 948 Linux report

**Good first line:** “OpenAI reported 1,169 working local root exploits across 948 distinct Linux kernel bugs.” This matches the research brief's majority-source wording; it still needs explicit OpenAI attribution because the primary post was inaccessible in that research pass.

Then explain the scan and why the two counts differ. State that local privilege escalation requires an existing foothold, that the model was unreleased, and that the figures were relayed by secondary reporting pending primary-source verification. Credit the actual outlets used in the ledger. End with one useful action such as “Send this to whoever patches your Linux fleet.”

**Reject:** “AI can now hack any Linux server. Share before they delete this.” It overstates remote access, invents urgency, and uses engagement bait.
