# Platform publishing support

Publishing access is account- and app-dependent. This is a map of documented API paths, not a claim that this app currently publishes to every platform. Configure a platform only after its app, scopes, user consent, and any required review are in place.

| Platform | Publishing path, access and review | Media / notable limits |
|---|---|---|
| Instagram | Instagram Platform for **professional** accounts (Business or Creator); OAuth user token with `instagram_business_basic` + `instagram_business_content_publish` (Instagram Login), or Facebook Login permissions. Meta app review/Advanced Access is needed for serving accounts beyond app roles/testers. | Image, video/Reel, and carousel publishing use a create-container then publish flow; media must be fetchable by Meta from a public URL. Stories are limited to Business accounts. [Publishing guide](https://developers.facebook.com/docs/instagram-platform/instagram-api-with-instagram-login/content-publishing) · [Permissions](https://developers.facebook.com/docs/instagram-platform/instagram-api-with-instagram-login/overview#permissions)
| Facebook Pages | Publish as a Page via Graph API with a Page access token, `pages_manage_posts` and `pages_read_engagement`; user must have a suitable Page task. OAuth and Meta app review/Advanced Access apply for external users. | Page posts support text and media-specific endpoints; image/video upload rules and limits depend on endpoint. Personal profile publishing is not provided by this Page publishing path. [Page posts](https://developers.facebook.com/docs/graph-api/reference/page/feed/) · [Permissions](https://developers.facebook.com/docs/permissions/)
| Threads | Threads API OAuth user token with `threads_basic` and `threads_content_publish`; request the scopes in Meta app setup/review for use beyond app roles/testers. | Text, image, video, and carousel via create container then publish; media URLs must be publicly fetchable. [Publishing guide](https://developers.facebook.com/docs/threads/posts/) · [Get started](https://developers.facebook.com/docs/threads/get-started/)
| LinkedIn | OAuth 2.0 member authorization. Member posts use `w_member_social` (Share on LinkedIn product); organization posts require `w_organization_social` plus an eligible Page role. Marketing API access is a separate approval path. | Organic text, image, video, document, article, multi-image, poll, and celebration posts; upload image/video assets first. [Posts API](https://learn.microsoft.com/en-us/linkedin/marketing/community-management/shares/posts-api) · [API access](https://learn.microsoft.com/en-us/linkedin/shared/authentication/getting-access)
| TikTok | Content Posting API app, Direct Post product configuration, user OAuth `video.publish` approval and user authorization. Unaudited clients are restricted to private visibility until TikTok audits the client. | Direct Post supports video and photo; video can be uploaded or pulled from a verified domain, photos require a verified URL/domain. Respect creator-reported privacy choices and duration. [Direct Post setup](https://developers.tiktok.com/doc/content-posting-api-get-started) · [Media restrictions](https://developers.tiktok.com/doc/content-posting-api-media-transfer-guide)
| YouTube | Google OAuth 2.0 user consent with `youtube.upload`; API enabled in a Google Cloud project. New/unverified API projects may have upload visibility restrictions; request audit/verification as applicable to lift them. | `videos.insert` uploads video media (up to 256 GB; video MIME types); metadata and privacy can be set. Quota and daily upload limits apply. [Upload endpoint](https://developers.google.com/youtube/v3/docs/videos/insert) · [Quota and auth](https://developers.google.com/youtube/v3/getting-started)
| Pinterest | Pinterest OAuth 2.0 user token with `pins:write`; normally also `boards:read` to choose a destination board. App registration and user consent required; access tier may constrain API usage. | Create image and video Pins on boards; supply image/video source or media upload fields supported by the Pin endpoint. [Create Pins](https://developers.pinterest.com/docs/work-with-organic-content-and-users/create-boards-and-pins/) · [OAuth](https://developers.pinterest.com/docs/getting-started/set-up-authentication-and-authorization/) · [Access tiers](https://developers.pinterest.com/docs/key-concepts/access-tiers/)
| X | X API v2 create-post endpoint requires user-context OAuth 1.0a or OAuth 2.0 Authorization Code with PKCE and `tweet.write` (plus user/read scopes as needed). API access is subject to X developer account/project access and plan limits. | Text posts and media attachments; upload media through the media upload API and reference media IDs when creating the post. [Create a post](https://docs.x.com/x-api/posts/create-post) · [Media upload](https://docs.x.com/x-api/media/upload-media) · [OAuth 2.0](https://docs.x.com/fundamentals/authentication/oauth-2-0/authorization-code)
| Bluesky | AT Protocol account session authentication; use OAuth for user-facing integrations where supported. No centralized app-review gate is documented for ordinary post creation, but service rate limits and account policies apply. | Create `app.bsky.feed.post` records; upload image blobs first. Up to 4 images per post, 2 MB each, with alt text supported. [Create post](https://docs.bsky.app/docs/tutorials/creating-a-post) · [OAuth](https://docs.bsky.app/docs/advanced-guides/oauth)
| Mastodon | Instance-specific OAuth authorization; register an app and request user token scope `write:statuses` (and `write:media` for uploads). No single central approval process: instance rules and limits vary. | Upload media, then attach media IDs to `POST /api/v1/statuses`; accepted formats and size caps are instance-configurable. Discover limits from the target instance. [Statuses API](https://docs.joinmastodon.org/methods/statuses/) · [Media API](https://docs.joinmastodon.org/methods/media/) · [Instance metadata](https://docs.joinmastodon.org/methods/instance/)

Treat platform limits as dynamic and validate against the account, API version, and instance at publish time. OAuth tokens and platform credentials belong in the backend, not browser code.
