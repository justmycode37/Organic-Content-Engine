# Account automation worker contract

`tickAccounts(container, env)` creates one durable queue row for the next upcoming account posting slot, within 24 hours. `(account_id, scheduled_at)` is unique, so repeated ticks are safe. Disabled accounts are skipped. Scheduling uses each account's IANA timezone and configured `postingTime`.

`claimAccountJob(container)` atomically leases one due pending job () and returns `{job:{id,lease,account:{id,name,topic,platform},scheduledAt}|null}`. A lease is exclusive and must accompany every subsequent operation. `heartbeatAccountJob(container,id,lease)` renews it. Expired paid work is marked for attention; generation is not automatically repeated after an uncertain operation.

The worker uploads the completed MP4 through the media route, then calls `completeAccountJob(container,id,lease,{materialId,spec,provenance})`. Completion binds that material to the durable account job; the account worker tick publishes it at the scheduled time through the scoped adapter. It never represents the post as published. `failAccountJob(container,id,lease,{code,message})` records a failure for inspection. Ambiguous publishing is marked for attention to prevent duplicate posts.

The durable queue is `account_automation_jobs`; `account_runs` remains the existing account-slot record. Health integrations should persist worker heartbeat under settings key `account_worker`.

Each claimed job keeps private diagnostics in `.account-cache/<job-id>/`: `failure.json` retains the timestamp, stage, original exception/stack/cause and structured provider diagnostics. Hedgy's `generation-events.jsonl` records each model stage before the request and its terminal status, request/response IDs, token usage and returned text. Renderer failures include the redacted stderr tail and exit code. A failed Site failure-report request is recorded separately in `failure-report-error.json`, preserving the original failure. Evidence also goes to the private worker log if the cache cannot be written. Configured credentials and bearer tokens are redacted before either sink; directories are owner-only and evidence files use mode `0600`. Public job errors use fixed stage/reason labels, with raw provider bodies confined to private evidence.

Hedgy retains `gpt-6.1-sol` at `xhigh` effort and streams Responses through a terminal event, without a client output-token cap or a two-minute request deadline. Reasoning consumes the output budget, so the former 3,000-token ideation cap could end a response before any visible text ([official OpenAI documentation](https://developers.openai.com/api/docs/guides/reasoning#allocating-space-for-reasoning)). Incomplete, failed, empty or interrupted responses fail explicitly with diagnostic evidence; transport failures do not trigger another paid request. The `paid-generation-started` guard still blocks automatic regeneration of uncertain paid work. Existing failed jobs are not requeued by a worker update.
